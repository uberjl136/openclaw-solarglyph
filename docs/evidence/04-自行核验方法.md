# 04 · 自行核验方法（评审方 5 分钟）

本作品不要求评审相信任何自述。**下面两条路径任选一条**，都能独立复现。

- **路径 A（5 分钟，不需要任何模型密钥）**：验证仿真服务、技能包完整性、引擎结果可复现
- **路径 B（约 15 分钟，需要自备一个大模型密钥）**：验证「一句话触发 → 智能体自主执行」

---

## 前置条件

| 项目 | 要求 |
| --- | --- |
| Node.js | **≥ 24.16.0**（OpenClaw 的 engines 要求；`node -v` 查看） |
| 磁盘 | ≥ 2 GB（仓库含上游快照） |
| 网络 | 克隆仓库需要；路径 A 全程离线可跑 |

```bash
git clone https://github.com/uberjl136/openclaw-solarglyph
cd openclaw-solarglyph
```

> 仓库体积约 155 MB（含 4.3 万个上游文件）。只关心自研部分的话，
> 看 `skills/`、`solarglyph-core/`、`docs/` 三个目录即可，`upstream/` 是原版快照，不必读。

---

## 路径 A：不接模型也能验证（约 5 分钟）

### A1. 启动仿真服务

```bash
node solarglyph-core/server.js
```

期望输出：`[solarglyph-simulation] listening on http://127.0.0.1:8787 (pid …, node v24.x)`

**另开一个终端**做后面的步骤。

### A2. 一键自检（7 项）

```bash
node scripts/verify-skill.cjs
```

期望结尾：**`all 7 checks passed`**，退出码 0。

这七项包括：技能元数据合规、技能副本与源逐字节一致、技能内引擎可独立加载、
两次运行结果一致、未知请求被拒、未知命令被拒、在线端到端跑通。

### A3. 四个场景的结果（证明数字是算出来的）

```bash
node smoke.cjs
```

期望看到四组互不相同的结果：

| 场景 | 年发电量 | 年回收热量 |
| --- | --- | --- |
| industrial-rooftop-5mw | 499.5 万kWh | 315.2 万kWh |
| industrial-rooftop-1mw | 109.2 万kWh | 117.6 万kWh |
| high-irradiance-10mw | 1569.4 万kWh | 217.2 万kWh |
| pv-thermal-storage-cooling | 150.0 万kWh | 43.1 万kWh |

### A4. HTTP 端到端（证明是异步任务服务）

```bash
node e2e-http.cjs
```

期望看到 `HTTP 202` + `Location` 头，接着一轮轮询轨迹
`5% → 25% → 50% → 70% → 90% → 100%`，最后 `succeeded`。

### A5. 中文指令触发（证明触发词映射）

```bash
node scripts/trigger.cjs "启动光伏余热仿真"
node scripts/trigger.cjs "西北高辐照 10MW"
```

期望两次结果不同（499.5 vs 1569.4 万kWh），说明是按指令选场景，不是固定输出。

### A6. 查看服务端留痕（可选）

浏览器打开 `http://127.0.0.1:8787/v1/simulations`，能看到刚才几次运行的任务记录，
带 `createdAt`、`durationMs`、`presetId`。

**这一步很关键**：记录是服务端写的，模型无法伪造。

## 路径 B：验证智能体自主调用（约 15 分钟）

需要一个大模型密钥（DeepSeek / 通义 / 智谱 等 OpenAI 兼容服务均可）。

### B1. 配置模型

在仓库根目录创建 `openclaw.json`（或直接用 OpenClaw 的 onboarding）：

```bash
cd upstream/openclaw-main
pnpm install --frozen-lockfile --ignore-scripts
pnpm build
export OPENCLAW_STATE_DIR=/path/to/your/state     # 自选一个空目录
pnpm openclaw onboard --auth-choice deepseek-api-key
```

> 也可以只填配置文件：在 `$OPENCLAW_STATE_DIR/openclaw.json` 里写
> `models.providers.deepseek.apiKey` 与 `agents.defaults.model: "deepseek/deepseek-v4-pro"`。
> 模型名以 `pnpm openclaw models list --provider deepseek` 输出为准。

### B2. 安装技能并启动

```bash
# 回到仓库根目录
npm run install-skill        # 或 node scripts/install-skill.cjs
cd upstream/openclaw-main
pnpm openclaw skills list | grep solar    # 应看到 ✓ ready 与 openclaw-workspace
pnpm openclaw gateway
```

浏览器打开 `http://127.0.0.1:18789/`，按提示填入网关令牌。

### B3. 一句话触发

在控制台里**新建一个会话**，输入框中只输入：

```
启动光伏余热仿真
```

**不要**指定技能名、脚本路径或参数。

期望：模型先显示「运行了 N 个命令, 读取了一个文件」，随后输出与截图 03 相同的指标表。

### B4. 交叉核对

```bash
curl -s http://127.0.0.1:8787/v1/simulations?limit=5
```

刚才那次对话应当对应其中**最新的一条**任务，`presetId` 为 `industrial-rooftop-5mw`。

> 本作品的截图 `05` 就是这样核对出来的：对话产生的任务号 `6c86a36f`
> 与服务端记录的第一条完全一致。

## 常见疑问

**Q：为什么 `upstream/` 里有 4 万多个文件？**
A：那是 OpenClaw 原版的完整快照，用于证明「用的是原版、且没有改动」。
评审只看自研部分的话，不需要读这个目录。

**Q：`npm start` 报找不到模块？**
A：请确认在仓库根目录执行，且 `solarglyph-core/` 目录存在。
`package.json` 的 `start` 指向 `node solarglyph-core/server.js`。

**Q：`node scripts/verify-skill.cjs` 第 7 项被跳过？**
A：第 7 项需要仿真服务在线。先完成 A1 再跑自检，就会显示
`trigger.cjs ran "启动光伏余热仿真" end-to-end against the live service`。

**Q：没有大模型密钥，能判断「智能体真的会调用」吗？**
A：可以看截图 03 与日志 03/05/06 三者的任务号对应关系；
也可以只做一个弱化验证：`node scripts/trigger.cjs "启动光伏余热仿真"`
走的是同一个技能目录里的入口与同一套 HTTP 接口，只是由脚本而非模型发起。

**Q：结果能复现吗？**
A：能。引擎对固定输入是确定性的（自检第 4 项专门校验两次运行输出一致）。
同样的场景参数每次都会得到 499.5 万kWh 这组数字。

## 一句话

**路径 A 验证「算得对、服务真、包完整」，路径 B 验证「模型自己会用」。**
两条路互不依赖，任一条走通都足以说明作品是真实可运行的。
